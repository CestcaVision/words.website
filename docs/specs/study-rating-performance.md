# 学习评分切卡性能

用户反馈：Again、Hard、Good、Easy 后等待时间过长，询问是否每次写数据库以及如何优化。

## 约束

正式评分仍须确认事务提交后再切卡，保存 FSRS、复习日志、学习时长和每日配额；保留幂等 eventId、卡片 version/epoch、账号隔离、时间回拨与新词上限保护。错词专项额外练习仍不提交 FSRS。

## 实现

- 前端评分热路径仅等待 `/review` 与 `/next`；词库、设置、AI 配置及完整统计在离开学习页时统一刷新。
- `/review` 返回已持久化的绝对日进度，用于更新学习页计数。重试不能累计两次；过时的总览响应不能覆盖新进度。
- 选择题干扰项只在一次学习会话首次需要时读取，切卡不重复下载整份词表。非词库页面不自动拉取单词列表。
- D1 的 next 直接 SQL 查询一张卡，优先到期重新学习卡；达到新词上限后仍可返回到期卡，不再读取全部单词或为读取 next 写计划。
- 评分只读取必要的卡片、幂等记录和当天计数，不计算完整速度统计。相关写入仍在一个版本守卫的 batch 事务中完成。
- 为复习队列、新卡队列和近期日志增加索引，统计困难词使用 COUNT 而非读取所有词条。

## 回归证据

`node --import tsx --test tests/study-performance.test.ts` 在真实 5040 词 fixture 上，旧实现读取 next 时传回 5042 行、5 次读取并排队一次计划写入；新实现传回 1 行、3 次读取、零排队写入。此处是数据库返回到 Worker 的行数，不等同 D1 的计费扫描行数。

Chrome + 本地 workerd/D1 交互验证四种评分各触发两个请求（review、next），均保存成功且新词计数为 4；本地测量每次约 105ms，不能直接视为公网延迟保证。真实公网仍包含浏览器到 Cloudflare 以及数据库往返延迟。
